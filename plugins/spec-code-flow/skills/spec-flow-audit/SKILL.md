# spec-flow-audit:關卡品質探測(變異測試)

先讀 `spec-code-flow` 總則。**這一步的執行者必須獨立於寫程式與測試的人**(實作者不要自己審自己的關卡)。

## 步驟

1. 確認基線:`gates`(specflow.json)全部 exit 0,否則 `mutate` 會拒絕執行。
2. `specflow mutate -n 40 --seed 1`(預設在暫存副本做,不動你的工作樹;`--gate "<指令>"` 可覆寫關卡)。
3. 看輸出 `mutation: K/N 被關卡抓到` 與每個 `SURVIVED` 的檔案行與突變內容。
4. 對每個存活突變分三類處理:
   - **等價突變**(改了也不影響行為,例如日誌、無效分支):記錄略過。
   - **測試盲點**(多半是邊界值、上限、最大編碼值):補測試並加 `@covers`,重跑到被抓到。
   - **規格沒說清楚**:該行為沒有需求支撐 ⇒ 補一條需求(或 `question`),再補測試。
5. 回報:抓到率、存活清單與你的分類、補了哪些測試。**抓到率不是品質分數**,只是盲點線索(實測中靠邊界測試把 9/10 補到 10/10)。
6. 排進例行(每季或每次大改後)。抓到率下降 = 測試跟不上程式。

## 限制

- 突變是文字層級(運算子與數字),不懂語意;macro、條件編譯、生成碼可能產生無效突變。
- `gates` 以 shell 執行,只放你信任的指令。
- 突變數 N 小時只是抽樣,不代表全覆蓋。
