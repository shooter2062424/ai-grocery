# Reference:依「給誰看、要達成什麼」拆設計策略

## 核心原則(比任何特效都重要)

> **同一個品牌、同樣的內容,可以拆成完全不同的網站——差別在「為誰、為什麼」。** 先決定 **受眾 + 目標 + 要追蹤的指標**,再決定結構與要不要動畫。華麗特效常以 **效能差、無障礙低** 為代價,不一定是對的選擇。

開工前先問使用者三件事:**這網站給誰看?你希望他看完做什麼?怎麼算成功(指標)?** 再從下面三種策略選一個(或混搭)。

## 三種策略(以「工作室/個人品牌站」為例)

### 版本 A:「讓客戶來找你合作」(轉換導向)
- **溝通邏輯:** 看到 → 信任 → 理解 → 行動。把網站設計成一條 **說服漏斗**。
- **結構:**
  1. **Hero** — 講清楚價值主張(你能帶來什麼)。
  2. **Trust Bar** — 合作過的品牌/數據,快速建立信任。
  3. **Projects** — 做過哪些案子(代表作)。
  4. **Services** — 你能做什麼。
  5. **Process** — 合作流程,降低「不知道怎麼開始」的門檻。
  6. **Awards / Testimonials** — 獎項數字 + 真實客戶證言,提高信任。
  7. **CTA** — 明確的聯絡/預約按鈕。
- **追蹤指標:** CTA 點擊率、聯絡表單完成率。

### 版本 B:「讓人看懂你在幹嘛」(敘事/差異化導向)
- **溝通邏輯:** 用 **敘事** 重新設計,網站像一本雜誌/一本書,凸顯思考方式做出差異化。
- **結構(分章節):**
  - **Hero** — 「我們用程式說故事」之類的定位,和競品拉開差距。
  - **Ch.1 Motion** — 展示方法論。
  - **Ch.2 Craft** — 細節工藝 + 數據佐證品質。
  - **Ch.3 System** — 系統思維,暗示「交付的是可持續的系統,不只是頁面」(長期價值)。
  - **Ch.4 Collaboration** — 客戶證言 + Trust Bar。
  - **CTA** — 用 **問句邀請**,而非按鈕推銷。
- **追蹤指標:** 閱讀深度——進站人數 vs 滑到最底看完的人數(驗證敘事假設)。

### 版本 C:「最快看懂重點」(極簡/效能導向)
- **溝通邏輯:** 把裝飾全拿掉,**品牌價值還剩什麼?** 資訊架構走 **最短路徑**。
- **結構:** Hero(直接講價值主張)→ Trust Bar → 三個精選作品 → 簡潔服務列表 → CTA。
- **動效:** 不用華麗動畫,只用 **最簡單的 CSS 互動**,追求速度/效率/效能。
- **追蹤指標:** **行動裝置聯絡轉換率**(手機網路不穩、耐心只有 ~5 秒,打開就能聯絡到人最關鍵)。

## 選擇指引

| 你的主要目標 | 選 | 重點 |
|---|---|---|
| 拿到客戶/詢盤 | A 轉換導向 | 說服漏斗 + 強 CTA + 信任證據 |
| 建立品牌調性/被記住/做出差異 | B 敘事導向 | 章節敘事、思考方式、閱讀深度 |
| 資訊快速送達、行動族群、效能優先 | C 極簡導向 | 最短路徑、極速、行動轉換 |

> **可混搭**:例如 A 的漏斗骨架 + B 的敘事 Hero;但別讓動畫蓋過目標。**先有策略,再決定要不要、以及哪裡放動畫。**

## 把策略接回實作

決定版本後 → 回 `modern-aesthetics.md` 選美學方向與技術棧 scaffold → 需要動畫再走 `scroll-animation-pipeline.md`。每個區塊都回頭問:**這個區塊服務了哪個指標?** 不服務目標的就砍。
