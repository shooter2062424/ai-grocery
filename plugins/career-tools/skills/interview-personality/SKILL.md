# Interview Personality(個人特質題)

## 這個 skill 在做什麼

面試裡的個人特質題,多數人會答:

```text
Hardworking / Responsible / A team player / Easy to work with
```

這些都沒錯,**問題是下十位應徵者也會這樣答**。

面試官真正想知道的不是你有幾個正面形容詞,而是:

> **跟你一起工作,到底是一種怎樣的體驗?**

因為整場面試在 45–60 分鐘裡,其實只在回答一個問題:

> **「我能不能想像這個人,在我的 team 裡工作?」**

你(Claude)的任務:**不是幫使用者挑漂亮的形容詞,而是幫他把特質變成面試官腦中的畫面。**

## 核心公式

```
Trait(你的特質) → Behaviour(它在工作上怎麼出現) → Evidence(具體例子)
```

| 層 | 回答什麼 | 少了會怎樣 |
|---|---|---|
| Trait | 你是什麼樣的人 | — |
| **Behaviour** | **這個特質在工作上「怎麼出現」** | 只剩形容詞,跟別人一樣 |
| **Evidence** | 有什麼事實支撐 | 像自我宣稱,面試官沒信心 |

## 啟動方式

當使用者說「我要準備面試」「同事會怎麼形容我這題怎麼答」「幫我看這段自我介紹」「我的答案是不是太通用」
「我下週面試 X 職位」時啟動。

**開始前先問三件事(一次問完,不要一題一題來回):**

1. **應徵什麼職位?公司是什麼性質?**(決定該把哪個特質排前面)
2. **面試語言是中文還是英文?**(直接用該語言產出成品)
3. **你手上有沒有現成的答案或履歷?**(有就以它為底改寫,沒有就從第一步開始挖)

## ⚠️ 最重要的一條:不要從形容詞開始挑

**多數人的錯誤做法是先挑一個好聽的詞,再硬找例子** —— 這樣挑出來的詞不像自己,例子也很牽強。

**正確的方向是反過來:從事件回推特質。** 問使用者:

> **「回想過去一年,同事在什麼情況下會來找你?」**

那個「情況」就指向他的特質,而且證據天然就在。

| 同事來找你的情境 | 反推出的 Trait |
|---|---|
| 事情亂掉、沒人知道下一步 | Calm decision-maker / Structured under pressure |
| 卡住了、需要有人想別的辦法 | Resourceful |
| 兩邊吵起來、需要有人翻譯 | Bridge-builder / Straightforward but supportive |
| 要做一件沒人做過的事 | Curious / First-mover |
| 東西要交出去前總是找你看一遍 | The last line of defense / Detail-anchored |
| 新人來了都被指派給你帶 | Coach-by-default |

若使用者一時想不到,**用具體提問把他挖出來**,不要直接給答案:

- 上一次專案出事,現場是誰先開口的?他做了什麼?
- 有沒有哪件事,別人做起來卡卡的,你做起來特別順?
- 你被稱讚過什麼?**用他們的原話,不是你的美化版**。
- 你離職/轉組的時候,同事最捨不得你哪一點?

## 執行流程

### 第一步|挖出 3 個候選 Trait

用上面的情境提問挖出事件,再一起收斂成 3 個候選詞。

**⭐ 選詞的判準:不要選最漂亮的,選最有辨識度的。**

好的候選詞長這樣:

```
Strategic · Calm under pressure · Resourceful · Curious · Straightforward but supportive
```

**辨識度從哪來?從「這個特質是有代價的」。**

| 特質 | 它的代價 | 所以有辨識度 |
|---|---|---|
| Straightforward | 可能得罪人 | ✅ |
| Curious | 可能離題 | ✅ |
| Strategic | 可能顯得算計 | ✅ |
| **Hardworking** | **沒有任何代價** | ❌ **所以誰都能說** |

**⭐ 進階手法:在安全的特質上加一個帶稜角的但書。**

```
❌ 我很好合作
✅ very easy to collaborate with, but also willing to challenge when needed
```

純粹的「很好相處」聽起來像沒有意見;**稜角才是辨識度的來源。**

⚠️ **但底線是誠實:是「從他真實的特質裡挑最相關的那個」,不是「編一個職位想要的人格」。**
第三層的 Evidence 會把假的揭穿。若使用者想用一個沒有證據支撐的特質,**直接告訴他這一點**。

### 第二步|把 Trait 展開成 Behaviour

**關鍵轉換:從「狀態」變成「動作」。**

```
❌ 狀態(被動、消極):我不會慌 / 我很好相處 / 我很負責
✅ 動作(主動、可觀察):我會先把相關的人拉進同一個會議
                    → 把問題拆成幾個已知與未知
                    → 定出接下來 48 小時要驗證什麼
```

**⭐ 檢查法:如果這段 Behaviour 可以原封不動套在別的特質上,那它太空了,退回重寫。**

範例改寫(冷靜可靠):

> **前:** My team would describe me as calm and reliable because I won't get panic when things go wrong.
>
> **後:** My team would describe me as **the calm decision-maker who stays calm when things get messy**.
> When a project becomes unclear or we hit an unexpected issue, **I tend to be the one who brings people
> together, structures the problem and works out what we need to do next.** For example, in XYZ, I…

注意差在哪:「不會慌」是**沒做什麼**;「把人聚起來 → 把問題結構化 → 定出下一步」是**做了什麼**。

### 第三步|每個 Behaviour 綁一個真實案例

不需要很大的事,但要有:**當時的情況 → 你做了什麼 → 結果**。

**⭐ 一定要準備兩個長度:**

| 版本 | 用在哪 |
|---|---|
| **30 秒版** | 預設先講這個 |
| **2 分鐘版** | 面試官追問才展開 |

⚠️ 若使用者給的案例裡**看不到他個人的貢獻**(全是「我們」),請他把「我做的那部分」單獨切出來。

### 第四步|針對職位重排順序

**先確認那個職位究竟需要什麼**,再決定先講哪一個。

| 職位 | 先講 |
|---|---|
| Project Manager | Calm + Structure + Stakeholder alignment |
| 新創早期成員 | Resourceful |
| 跨部門協調角色 | Straightforward but supportive |
| 研究/探索型職位 | Curious |

**⭐ 不用改內容,改順序就好。** 同一組三個 Trait,面不同職位時換順序即可。

### 第五步|產出成品

給使用者一份可以直接背的東西,格式如下:

```markdown
## 主打:<Trait>
**一句話開場(30 秒版):**
My team would describe me as <trait with edge>. When <trigger situation>,
I tend to be the one who <verb 1> → <verb 2> → <verb 3>.

**例子(30 秒):** <情況 → 我做了什麼 → 結果>
**例子(2 分鐘,追問才用):** <展開版>

## 備援 1:<Trait>  （面 <某類職位> 時改講這個）
…
## 備援 2:<Trait>
…
```

**用使用者指定的面試語言產出**(英文面試就給英文句子,不要給中文再叫他自己翻)。

## 收尾時一定要提醒的三件事

1. **⚠️ 追問缺點怎麼辦** —— 第一步選的那個「有代價的特質」,它的代價就是最誠實的答案。
   例:`Straightforward` 的代價是「有時候講太快、沒先鋪陳」——**接著說你怎麼管理它**,這題就穩了。
   **主動幫使用者把這個備援答案也準備好。**
2. **⚠️ 這題會變形** —— 「你的前主管會怎麼形容你?」「如果我打給你的 reference 他會說什麼?」
   **同一套公式適用,但主詞換人,例子也要換成那個人真的看得到的事**(主管看得到的和同事看得到的不一樣)。
3. **⚠️ 注意文化差異** —— 這套講法在英語系面試很標準;
   **在部分較保守的環境,過度包裝的自我描述可能被視為浮誇** ——
   建議把 Evidence 講得更重、形容詞講得更輕。

## 不要做的事

- ❌ **不要直接丟一堆形容詞讓使用者挑** —— 那會回到「先挑詞再硬找例子」的錯誤路徑。
- ❌ **不要幫使用者編造案例。** 若他提不出證據,就換一個他提得出證據的特質。
- ❌ **不要把三個特質都寫成完整長答案** —— 面試只講得完一個主打 + 一個備援,其餘只需關鍵字。
- ❌ **不要用 STAR 這種縮寫術語去指導使用者**,除非他自己先提到。直接給句子比給框架有用。
