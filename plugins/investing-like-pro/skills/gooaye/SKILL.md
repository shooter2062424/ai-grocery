# gooaye — 用股癌的投資思維評斷一支股票

## 這個 skill 在做什麼

拿一支股票進來,**用股癌(謝孟恭)累積數百集 podcast 萃取出的「評斷準則」去判斷它好不好**——
不是去查「股癌最近有沒有推薦它」,而是套他的思維框架(估值算法、基本面指標、題材純度、護城河、
預期差、循環股紀律、風控)逐維度檢驗,最後給出「好 / 普通 / 避開」的模擬結論。

> **核心理念(這版的重點):** 一支股票好不好,**先用框架算出來**;股癌近期看好/推薦什麼,**只當輕度輔助**
> (最後微調信心),不是判斷的主軸。他自己就反覆說「別因為某人推薦就買,要自己知道在買什麼」。

> ⚠️ **重要聲明(每次回答都要讓使用者意識到):** 這是對一位真實公開人物 **方法論的模擬與推斷**,
> **不是謝孟恭本人的意見,也不是投資建議**。指標數據來自第三方 API 可能有誤;投資前請自行查證、自負風險。
> 本 skill 與股癌/謝孟恭 **無任何關聯**。

## 啟動時機

使用者說「股癌會覺得這支股好不好」「用股癌邏輯評/挑 X 股」「這檔該不該買(股癌視角)」
「用股癌框架幫我看這個題材/族群」「股癌會怎麼分析這檔」等。

## 核心:先讀框架(references/investment-framework.md)

**回答前先讀 `references/investment-framework.md`** ——這是本 skill 的大腦,包含:
分型(成長/題材/循環/防守/平台壟斷)、七大評斷維度(各維度的指標+決策規則+EP 佐證+紅旗)、
verdict 模板、紅旗總表。**評斷一律以它為主。**

## 評斷一支股票的流程

```
1. 讀 references/investment-framework.md(核心框架)
2. 給股票「分型」→ 決定最該看哪些指標
3. 撈指標:python scripts/fetch_indicators.py <代號>
     台股用純數字(2330);美股用英文代號(NVDA)。
     ★ 動態原則:循環股要再撈稼動率/報價、題材股要查營收佔比/BOM 純度、
       成長股要看 forward EPS 與成長率——必要時「改寫/擴充這支腳本」或另寫查詢,
       因為股癌重視的指標會因股票類型而不同(框架已說明)。
4. 逐七維度評分 + 過紅旗清單
5. 疊加「輕度輔助」:讀 references/recent-stance.md / recency-ranking.md,
     只用來±微調信心(見下),不主導
6. 用框架的 verdict 模板輸出:好/普通/避開 + 理由 + 風險 + 操作 + 免責
```

## 指標工具(scripts/fetch_indicators.py)

撈「股癌看重的指標」,輸出對齊框架:

| 市場 | 來源 | 撈到的指標 |
|---|---|---|
| 台股(數字代號) | FinMind 開放 API(免 token,設 `FINMIND_TOKEN` 可拉高額度) | 本益比/淨值比/殖利率、近一年 PE 區間、月營收+YoY(近3月趨勢)、近兩季毛利率/營益率/EPS、近5日三大法人買賣超 |
| 美股(英文代號) | yfinance(`pip install yfinance`) | trailing/forward PE、PEG、P/S、毛利/營益率、營收與獲利成長率、市值、殖利率 |

```bash
python scripts/fetch_indicators.py 2330        # 台積電
python scripts/fetch_indicators.py NVDA        # 輝達
python scripts/fetch_indicators.py 2330 --json # 機器可讀
```

> 這支腳本只給「原始指標 + 簡單衍生」;「好不好」由 AI 套框架的決策規則判讀。
> **它是起手式,鼓勵按股票類型動態改寫**(框架 D 節要查 BOM/營收佔比、F 節要查稼動率/報價,
> 這些需要另查產業資料或法說會,腳本不一定涵蓋)。

## 「輕度輔助」記憶層(降級使用)

這幾個檔是 **從逐字稿確定性萃取的近期立場**,**這版把它降為輔助**——只在框架算完後微調信心:

| 檔案 | 用途 | 怎麼用(輔助) |
|---|---|---|
| `references/recent-stance.md` | 他近期看多/看空與操作心態質化摘要 | 框架判好且他也偏多→信心↑;判好但他轉謹慎→照框架走並註明 |
| `references/recency-ranking.md` | 個股/題材近期加權排名 + 升溫/退燒 | **提及頻率≠看多**;只看「他最近是否在意這領域」 |
| `references/ranking.json` | 上者結構化版 | 要精確排序/篩選時 |
| `references/mention-timeline.json` | 每標的逐集提及時間軸 | 用 Grep 查某檔「他從哪集開始談、何時最熱」 |

> ⚠️ **不要把「他最近有沒有推薦」當成股票好壞的判準。** 推薦只代表「值得用框架檢驗的候選」。

## 應用案例

- **「用股癌邏輯看台積電(2330)現在算好嗎?」**
  → 讀框架 → 分型:成長＋平台壟斷 → 撈指標(PER≈32、毛利 66%、EPS 季增、營收 YoY +17%)
  → 套規則:用 forward EPS 而非過去 EPS、AI Peer 裡相對便宜(EP656)、護城河極深;
  紅旗少 → 模擬結論「長期看好、核心持股級,但高檔不追、回檔分批、控水位」;
  輔助層:他近期確實偏多(recent-stance)→ 信心↑。附免責。

- **「幫我用股癌框架評一檔『只沾到衛星題材』的小股」**
  → 分型:題材股 → 重點查 **營收佔比/純度**(框架 C);若佔比個位數且三年拉不起來 → 觸發紅旗 5
  → 結論偏「避開/觀望」,即使最近股價噴。**不因它最近熱門就給高分。**

- **「記憶體股現在能追嗎(股癌視角)?」**
  → 分型:景氣循環股 → 套框架 F:看稼動率/報價、成本 vs 需求驅動、是否高檔+業者囂張+擴產共識
  → 提醒「循環股低 PE 常是賣點」、他自己 EP608 被洗掉五成的教訓 → 結論偏謹慎。

- **「股癌最近在關注什麼?」(純資訊查詢)**
  → 這題才直接讀 `recent-stance.md` + `recency-ranking.md` 回答,並聲明「頻率≠看多、非建議」。

## 記憶如何更新

- **框架(investment-framework.md)**:方法論,變動慢;當股癌明顯改變選股邏輯時才更新。
- **輔助記憶(recent-stance / recency-ranking / *.json)**:每週日 cron 重跑 `scripts/build_memory.py`
  (抓最新逐字稿→重算提及時間軸/排名),並由 AI 依最近約 60 集重寫 `recent-stance.md`。詳見 `references/methodology.md`。
